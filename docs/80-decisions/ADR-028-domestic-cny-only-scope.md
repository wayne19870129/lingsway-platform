# ADR-028: 只面向国内用户，只收人民币，只用微信/支付宝

- 状态: **已接受（Accepted）**
- 日期: 2026-09-18（User 直接拍板）
- 决策范围: 目标市场、结算币种、收款渠道。约束
  `backend/app/models/billing.py` 的币种默认值、
  `backend/app/providers/payment/**`、以及所有金额展示。
- 补充: **ADR-004**（支付保持人工确认，不接 webhook）。本 ADR 不改变
  ADR-004 的任何结论，只是把它没写的市场与币种边界补上。

## 决定

1. **目标用户只有中国大陆。** 不做国际化，不做多地区。
2. **结算币种只有人民币（`CNY`）。** 系统中不存在第二种币种。
3. **收款渠道只有微信支付与支付宝**，且按 ADR-004 保持**人工确认**
   （收款码 + 客户点「我已付款」+ Telegram 通知 + 管理员核对）。
4. **永不接受**：美元或任何外币、USDT 或任何虚拟币/加密货币、
   境外支付渠道（Stripe / PayPal 等）。

这不是"暂时先这样"。它是一条**范围边界**，和 `README.md`「明确不做的事」
同级：任何把多币种、汇率、加密货币或境外渠道引入本系统的提案，都必须先
撤销本 ADR，而不是"顺手加个开关"。

## 为什么要专门写一条 ADR

ADR-004 只裁定了「怎么确认收款」，没裁定「收什么钱、收谁的钱」。这个缺口
在代码里留下了两处与事实相反的默认值（见下），而且每次讨论定价时都要重新
解释一遍。写下来之后，后续实现者不需要再推导。

## 已修正的两处错误默认值

核对当前 `main` 后发现并在本 PR 修正：

| 位置 | 原值 | 现值 | 影响 |
|---|---|---|---|
| `models/billing.py` `Plan.currency` | `default="USD"` | `default="CNY"` | 迁移 0001 的该列**没有 server_default**，Python 侧默认值是唯一来源。原值会让任何未显式指定币种的 `Plan` 行变成美元，而前端渲染的是 `{price} {currency}`——客户会看到 "30 USD"，并经 `Order.currency = plan.currency` 一路带进订单 |
| `providers/payment/mock.py` | `PaymentIntentDTO(..., "USD")` | `"CNY"` | mock 也不该示范一个本系统不存在的币种 |

`Order.currency` **没有**默认值（`String(3)`，必填），始终显式取自
`plan.currency`，因此不需要改动。

**不新增迁移。** 这两处都是 Python 侧默认值，只影响未来经 ORM 创建且未显式
指定币种的行；已有行不受影响，也不应被本 ADR 批量改写——存量数据的核对是
运维动作（见下）。

## 仍需人工核对的存量数据

仓库里**没有任何代码创建 `Plan` 行**（`deploy/lib/60_seed.sh` 显式拒绝隐式
种子数据），所以 `backend/app/catalog.py` 声明的四档只是声明。**上线前必须
人工核对 `plans` 表的现有行**：四个 `plan_code`、`price`、`duration_days = 30`，
以及**尤其是 `currency`**——如果存量行是 `USD`，本 ADR 的修正管不到它们。

## 对展示的要求

面向国内客户，金额应展示为 **`¥30`**，而不是 `30 CNY`。当前前端渲染的是
`{price} {currency}`（`(customer)/plans/page.tsx`、`orders/new/page.tsx`、
`orders/page.tsx`、`(admin)/admin/orders/page.tsx`）。

本 ADR **不在此 PR 内改前端**——那几个文件是单行千字符写法，改动风险与收益
不匹配，且 `TASK-S07` 本来就要动其中三个。该项已写入 TASK-S07 的前端验收，
在那里一并完成。

## 不做的事

- 不引入货币格式化库或 i18n 框架。单一币种单一地区，不需要。
- 不引入汇率、多币种定价表、或 `currency` 的运行时可配置化。
- 不接任何支付 webhook（ADR-004 已裁定，本 ADR 不放宽）。
- 不批量改写存量 `plans` 行——那是运维动作，需人工核对后执行。

## 重新评估条件

- 若将来确实要面向境外用户，本 ADR 必须整体重写，而不是加一个
  `SUPPORTED_CURRENCIES` 开关——多币种会波及定价表、订单、账务、
  展示与对账全链路，不是一个配置项能覆盖的。
- 若监管或渠道变化导致微信/支付宝不可用，收款渠道一节需要重新评估；
  但「只收人民币」与「只面向国内」两条独立成立，不随渠道变化。
