# ADR-012：订阅渲染以旧生产实现为行为基准

- 状态：已接受
- 日期：2026-09-03

## 问题

新仓库的 `backend/app/domain/subscription_render.py` 是一个纯函数抽象，
但旧生产实现已经形成客户可见的订阅行为。旧实现包含
`Subscription-Userinfo` 响应头、ETag、`stash` 与 `v2rayng` User-Agent
识别、完整的 VLESS Reality 字段，以及重名代理的名称去重。这些行为不能
因为迁移到新的抽象层而丢失。

## 决定

扩展新 domain 渲染器，使其覆盖旧生产行为，而不是削减旧行为去迁就新的
纯函数抽象。domain 层继续只接收调用方提供的数据，不读取数据库，也不
调用 provider；响应头数据由调用方传入，渲染结果负责携带。

13 条分流规则从未在生产实现。当前代码中的 `CORE_RULES` 是新写的目标
状态，本轮保留定义但不接入订阅渲染路径；是否启用由
`docs/82-tasks/TASK-T13-split-routing.md` 另行决定。

此前将“首条 private BLOCK、末条 tcp/udp BLOCK、无 DIRECT 兜底”认定为
客户订阅渲染不变式，是错误的。三条不变式属于 Xray 服务端路由，不适用于
客户订阅 YAML，因此不作为本 ADR 所覆盖的订阅渲染验收项。

## 约束

1. User-Agent 归一化与旧实现一致：转小写、下划线转空格、多空格归一。
2. 规则默认保持为唯一的 `MATCH,SUBSCRIPTION`。
3. 订阅渲染不得引入数据库、文件、网络或 provider 副作用。
4. 13 条规则只能通过 T13 的灰度与回退流程启用。

## 后果

迁移后的客户订阅继续保持已验证的生产兼容性，同时纯函数 domain 接口
仍然可以独立测试。未来启用客户端分流时，需要单独完成客户端数据库能力
确认、单订阅灰度和一键回退验证。
