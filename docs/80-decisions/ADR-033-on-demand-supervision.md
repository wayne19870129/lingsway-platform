# ADR-033: 监督改为 User 触发；放弃"定期监督"

- 状态: **已接受（Accepted）**
- 日期: 2026-09-19
- 决策范围: ADR-030 §4（监督节奏）、ADR-031 §7、ADR-032 §6 中"不弱化定期
  监督"三条；`docs/85` §0 / §4.0 / §4.1 / §6.1；`AGENTS.md` 的角色段。
- 触发来源: User 明确要求——"你还是不要定期去审查了，我觉得由我来触发这个
  审查吧。当我觉得有一个大块需要审查的时候，我会给你命令，然后你再去审查，
  看架构、看细节。现在主要就是你把架构定好之后，主要还是用 ChatGPT 和
  Codex 去把代码库先弄完。"

## 1. 决定

**Claude 不再按节奏自行唤醒审查流水线。审查由 User 触发。**

| | 之前（ADR-030 §4） | 本 ADR 之后 |
|---|---|---|
| 谁决定什么时候审 | Claude 自行低频唤醒 | **User 下令时** |
| 审什么 | 健康摘要 + 按信号深入 | **User 指定的那一块**：架构、细节、或整条线 |
| 实时盯过程 | 不做 | 不做（不变） |
| 拉闸权 | Claude 单边可拉，不可单边复机 | **不变**（ADR-030 §5a 完整保留） |

Claude 的日常职责收敛为：**把架构定好，写 ADR 与 TASK，然后让开**。
代码由 ChatGPT 指挥、Codex 执行。

## 2. 本 ADR 正在撤销三条"不许弱化"的条款，这一点必须写明白

不能假装这是一次无痛调整。被动到的三条，每一条当初都是**特意**写下来防止
后来者随手放松的：

| 出处 | 原文要点 |
|---|---|
| ADR-030 §4 | 监督"默认低频"但**存在**；并列出强制介入节点 |
| ADR-031 §7 | 「**不因为"Codex 现在只执行"就弱化 ADR-030 的定期监督**」 |
| ADR-032 §6 | 「**不弱化 ADR-030 的定期监督**——执行者换了，ADR-031 §3 记录的
"执行端没有冗余校验"这个性质没变」 |

ADR-031 §3 给的理由到今天仍然成立：**指令卡越具体，Codex 越像一只手——
指令本身错了它不会拦住**，所以执行端没有冗余校验。这个性质**没有**因为
本 ADR 而改变。**本 ADR 不反驳那条理由，而是主张它现在被另一样东西顶着——
见 §3。那样东西一旦消失，这条 ADR 就必须重算（§8）。**

## 3. 为什么现在可以接受：User 本来就在每个 PR 的环里

定期监督要防的是**"没人看着的时候流水线一直转"**。它的风险与
**自动合并在 User 未参与下真实合并掉的 PR 数量**成正比。

**这个数量目前是 0。** 实测（2026-09-19）：

- S08 自动合并已上线并验证过判定逻辑，但**至今没有一个 PR 是被它合并的**；
  #136 / #137 / #140 / #141 / #142 / #144 / #145 / #146 / #147 全部由 User
  人工合并，#135（Dependabot）也是。
- 下一个业务任务 S07 已经写明**打 `no-automerge`、由 User 人工合并**
  （`docs/85` §5.0）。
- Dependabot 类 PR **结构上走不通闸门**（发不出带写权限的 `Verdict: PASS`），
  只能人工合。

也就是说：**User 现在是每一个 PR 的最后一道人工关口。** 在这个前提下，
再加一层 Claude 的定期审查，多出来的不是安全，是成本——而 User 已经明确
把成本放在优先级上（"主要还是用 ChatGPT 和 Codex 来干活"）。

**注意这个论证依赖的是事实，不是意图。** 它成立与否可以被数出来：
去数有多少 PR 是 workflow 合的。不是"我们打算人工合"。

## 4. 保留什么（这些**不**随监督一起取消）

1. **健康摘要继续采集。** `.github/workflows/pipeline-health.yml` 每 2 小时
   照常跑。它没有 LLM、没有凭据、成本可忽略，而且它的产出现在变成
   **按需审查的输入**——User 叫审查时，`pipeline-health` 分支上有一条连续
   的历史可读，而不是从零开始重建现场。**取消采集会让按需审查变贵，
   所以不取消。**
2. ~~**ADR-029 §6 的两个硬闸门不受影响**：接线任何真实外部系统之前
   （Webshare / Mihomo 生产激活）、任何生产部署之前，**必须**先做安全边界
   复核。这两条是**事件触发**的强制点，从来就不是"定期监督"的一部分，
   不在本 ADR 的撤销范围内。~~
   **2026-09-19：本条已被 ADR-034 撤销**（User 决定：不再存在任何"到了某个
   事件节点就强制必须叫 Claude"的规则）。**注意区分**：取消的是"必须让
   Claude 审一遍"，**不是**"必须有人批准"——`AGENTS.md`「禁止自主执行」
   整张表仍然要求人工确认，生产部署仍是人工的。论证见 ADR-034 §2，
   代价见 ADR-034 §3。
3. **拉闸权与复机的不对称**（ADR-030 §5a）**一字不动**：Claude 仍可单边把
   `.github/automerge-enabled` 置为 `false`，复机仍必须由 User 人工合并。
   本 ADR 改的是"什么时候去看"，不是"看到问题能做什么"。
4. **`docs/85` §6.1 的三层熔断全部保留**，并且第三层的地位上升——见 §6。

## 5. 诚实记下代价：健康摘要现在没有固定读者

这是本 ADR 最实在的损失，不要用"按需审查时会看"糊过去：

**摘要每 2 小时生成一次，`alerts` 字段会累积，而没有任何人或程序被安排去
定期读它。** `docs/85` §4.0 原本写着「自动合并开启后，这是 `main` 之后
唯一的独立检查」——本 ADR 之后，那句话的后半截不再成立：**`main` 之后
在 User 下令之前没有独立检查。**

采集与判断是两件事。**本 ADR 保住了采集，放弃的是定期判断。**
`ALERT_MAIN_CI_RED`、`ALERT_ROUNDS_AT_CAP`、`ALERT_THREE_AUTOMERGES`
这些信号仍然会被算出来、写进摘要，**但它们不会主动找到人**。

把这一条写清楚的目的是：将来若有人问"当初为什么没人发现"，答案在这里，
不是一次疏忽。

## 6. 第三层熔断从装饰变成承重

`docs/85` §6.1 第三条——**连续自动合并 3 个 PR 之后暂停派活、出一次进度
汇报、等 User 一句话再继续**——在本 ADR 之后是**把人重新拉回环里的主要
机制**，不再只是防"无限链"的保险。

**因此它不再是 ChatGPT 可以"顺手跳过"的一条。** 它由 ChatGPT 行为遵守，
平台不强制（与返工轮次上限同理，见 `CLAUDE.md`），所以：

> **任何放宽第三层熔断的提议，必须先重新评估本 ADR。**

## 7. 不做的事

- **不取消健康摘要的采集**（§4.1）。
- **不放宽 ADR-029 §4 的六个合并条件**，不放宽 3 轮返工上限，
  不放宽铁律 1–8。
- **不动 ADR-030 §5a 的停机/复机不对称。**
- **不把 TASK / ADR 的撰写权交出去**（ADR-029 §7、ADR-032 §3a 不变）。
- **不实时盯过程**——这一条本来就不做，本 ADR 不是把它改成"更少"，
  而是把"定期"这一档也去掉。
- **不声称这样更安全。** 它更省，安全性靠的是 §3 那个可以被数出来的事实。

## 8. 重新评估条件

- **只要出现第一个由 workflow 自动合并、且 User 事前未看过的 PR**，§3 的
  论证立刻减弱；累计到 3 个（即第三层熔断触发一次）时，**必须重新评估
  本 ADR**：要么恢复定期监督，要么给健康摘要安排一个机械读者。
- 若 `main` 上出现一次本可由摘要 `alerts` 提前发现、却因无人阅读而漏掉的
  缺陷，本 ADR 即告失效，按 §5 记录的代价重算。
- 若第三层熔断被发现没有被实际执行（连续合并 3 个之后没有汇报），
  §6 的前提不成立，同样必须重算。
- 若 User 恢复"按节奏审查"的要求，直接撤销本 ADR 即可——ADR-030 §4 的
  机制没有被删除，只是不再被触发。
