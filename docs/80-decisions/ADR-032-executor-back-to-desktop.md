# ADR-032: 执行者退回 Codex 桌面版；ChatGPT 重新承担指挥；放弃"无人值守"目标

- 状态: **已接受（Accepted）**
- 日期: 2026-09-19
- 决策范围: ADR-030（Claude 承担派发）、ADR-031 §1（执行者模型前提）、
  `docs/85` §0 与 §2、`docs/86` 全文。
- 触发来源: Codex Cloud 实测不可用（额度与模型档位均不可控），User 决定
  退回「ChatGPT 网页版做大脑 + Codex 桌面版执行 + Claude 定期审查」。

## 1. 先更正 ADR-031 §1 的一个事实错误

ADR-031 §1 那张表把执行者写成 **「5.6 Luna，轻推理」**，并把它当作整条
决策的**前提**。**这个前提没有被验证过，而且现在有反证：**

- 2026-09-19，Codex Cloud 被直接问到时自报 **「GPT-5.6 Sol」**，不是 Luna；
- Codex Cloud 的环境创建与设置页面**没有模型选择器**，用户无法指定；
- 它同时明确表示**无法读取或证明**平台为该次运行设置的 `reasoning effort`。

（最后一点它答得对：模型自报身份本身也不是可靠证据。所以正确的结论不是
"其实是 Sol"，而是**"执行者的型号与推理档位既不可控、也不可验证"**。）

**真正成立的前提，是能力不对称这件事本身**——指挥侧推理强、额度宽，执行侧
两者都弱——而不是任何具体产品名。ADR-031 的结论（判断在指挥侧、执行侧只
照着做、指令卡要写到不需要思考）**不受影响，依据被换成可验证的那一条**。

**教训单独记一笔：把一个无法验证的事实写进 ADR 的"前提"栏，会让整条决策
看起来比实际更有依据。** 以后前提栏只写能验证的东西；不能验证的写进
"未验证假设"，并说明如果它不成立会怎样。

## 2. 为什么放弃 Codex Cloud

两条，都是实测：

1. **额度不够，且无法只用便宜档位。** 页面不提供模型/推理强度选择，
   所以"用轻推理省额度"这个策略**根本无法实施**。
2. **它自己推不了分支。** 沙箱没有 git 凭据
   （`fatal: 'origin' does not appear to be a git repository`），
   每个任务都必须人工点一次"Create PR"。

第 2 条本身可以忍；第 1 条不能——ADR-031 的整个成本模型建立在"执行侧用
便宜档位"上，而那个开关不存在。

**要公平记一句：Codex Cloud 的行为是合格的。** 它守住了「允许修改的文件」
清单、跑完了全部验收命令、贴了真实输出、推送失败时诚实上报、没有 TASK 时
拒绝动手。**不通的是这条路的平台约束，不是执行者的纪律。**

## 3. 新分工

| 角色 | 负责 | 不负责 |
|---|---|---|
| **User** | 业务需求、验收、合并治理/审计 PR、**开着电脑** | 写代码 |
| **ChatGPT 网页版**（大脑） | 读派发队列选任务、把任务交给 Codex 桌面版、审查 PR、写指令卡 | 写 TASK/ADR；改代码；合并 |
| **Codex 桌面版** | 按 TASK 实现、跑验证、建分支、提 PR、按指令卡返工 | 决定做什么、扩大范围、自行合并 |
| **Claude Code** | 架构、撰写 ADR 与 TASK、**定期监督**、必要时拉闸 | 日常实现；实时盯过程；合并 |
| **Codex Cloud 代码审查** | 自动审 PR（**保留**，见 §5） | 任何判定权 |
| **GitHub workflow** | 条件全满足时机械合并 | 做任何判断 |

**ADR-030 把派发权移给 Claude 的那一条，本 ADR 予以撤销。** 派发回到
ChatGPT。

### 3a. 那 ADR-030 §2 的安全论证怎么办

ADR-030 把派发移给 Claude，是为了消除 ADR-029 记录的反对意见 #1：
**审查者在审查自己规格下产出的代码**。现在派发回到 ChatGPT，这个问题会
回来吗？

**不会，只要 TASK 文件仍然由 Claude 独占撰写。** 关键区分是：

- **"派发"** = 把已经写好的 TASK 交给执行者去做 —— 谁做都行；
- **"规格"** = TASK 文件里的目标 / 约束 / 允许修改的文件 / 验收标准 ——
  **这才是审查的判据**。

ChatGPT 审查时对照的是**它没有写的那份 TASK**。独立性保在规格这一层，
不在派发动作这一层。**所以 `AGENTS.md` 写权限表里"`docs/82-tasks/` 与
`docs/80-decisions/` 由 Claude Code 独占"这条，是本次调整能够成立的唯一
理由，不得随之放松。**

## 4. 放弃"无人值守"这个目标，明确写下来

Codex 桌面版跑在 User 的电脑上。**因此：**

- **User 的电脑不开，整条流水线就不前进。** 这是本 ADR 接受的代价。
- 之前几次讨论里出现过"以后就不用开电脑了"的说法，**从本 ADR 起不成立**，
  不要再按那个前提设计任何东西。

**仍然不需要电脑的部分**（这些在云上，与执行者无关）：CI、自动合并、
健康摘要、Codex Cloud 的代码审查、Claude 的监督。

## 5. Codex Cloud 的代码审查**保留**

执行搬回桌面版，但 Codex Cloud 的 PR 自动审查**继续开着**，理由：

- 它是**按 PR 触发的，与谁推的分支无关**——2026-09-19 它审的 PR #142 就是
  Claude 推的；
- 它已经证明有真实价值：在 #142 上抓到一个跨步骤的逻辑缺陷
  （比较基准读错分支，会导致每 2 小时一次空提交），那不是格式问题；
- 它**不消耗执行侧额度**，也不参与判定——`author_association` 是 `NONE`，
  自动合并网关不认它的 verdict（已实测）。

**所以它是净增的一双眼睛，零代价。** 关掉它没有任何理由。

## 6. 不做的事

- **不把 TASK / ADR 的撰写权交回 ChatGPT**（ADR-029 §7 不变，且它是 §3a
  成立的前提）。
- **不放宽 ADR-029 §4 的六个合并条件**，不放宽 3 轮返工上限，
  不放宽铁律 1–7。
- **不弱化 ADR-030 的定期监督**——执行者换了，ADR-031 §3 记录的"执行端没有
  冗余校验"这个性质没变。
- **不再声称流水线可以无人值守**（§4）。
- 不关闭 Codex Cloud 的代码审查（§5）。

## 7. 重新评估条件

- 若 Codex Cloud 将来开放模型/推理强度选择**且**额度可用，可以重新评估
  §2——但要先补一次实测，不要凭页面上出现了选项就认定可用。
- 若 ChatGPT 的派发与审查之间出现"为了让自己的派发通过而放松审查"的迹象，
  §3a 的论证即告失效，派发权必须再次移走。
- 若"必须开电脑"成为实际瓶颈（任务积压肉眼可见），重新评估执行者的选择，
  而不是重新评估 §4 的诚实记录。
